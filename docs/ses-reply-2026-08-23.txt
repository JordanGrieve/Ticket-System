HOW WE MAINTAIN RECIPIENT LISTS

Confirmed opt-in only, with no exceptions and no path around it.

A person types their address into a signup form. We store nothing at that point — submitting the form writes no database record at all. Instead we email them a confirmation link carrying a signed token, and the subscriber row is created only when they click it. The practical effect is that an address cannot be added to any list by anyone except the person who can read that mailbox, so a stranger cannot subscribe someone else, and a customer cannot type addresses in by hand.

We do not import purchased lists, we do not append addresses from data brokers, and there is no code path that creates a subscriber without a confirmed click.

For every subscriber we keep the evidence: the consent method, the timestamp of the confirming click, the URL of the page the form was on (read from the browser's own Origin/Referer headers, never from a field in the request body a caller could set), and the IP address the confirmation came from. An address with no consent record is excluded from every send by the audience-selection query itself, not by convention or by a checkbox someone might forget.

HOW WE MANAGE UNSUBSCRIBES

Every message carries RFC 8058 one-click headers — List-Unsubscribe with an https endpoint, and List-Unsubscribe-Post: One-Click — plus a visible link in the footer. The link is per-recipient and requires no account and no login.

Unsubscribing writes to a suppression list that is enforced inside the same SQL statement that claims each recipient for sending, so an opt-out that arrives in the middle of a send takes effect for that send rather than the next one.

HOW WE MANAGE BOUNCES AND COMPLAINTS

Bounce and complaint notifications are delivered to the SNS topic
arn:aws:sns:eu-west-1:479127223828:postbox-ses-feedback
and consumed by an endpoint that verifies the SNS message signature and pins the expected topic ARN, so it cannot be driven by forged traffic. That subscription auto-confirmed against AWS, which is the practical proof the verification path works rather than a claim about it.

Permanent bounces and all complaints are added to the suppression list immediately and the subscriber is marked accordingly. Transient bounces are recorded but do not suppress, so a temporarily full mailbox does not silently cost someone a subscription they asked for. A suppressed address is never resurrected by a later signup or import.

I am the sole operator and I watch these rates directly. If either rises, I stop the affected customer's sending rather than let it continue.
